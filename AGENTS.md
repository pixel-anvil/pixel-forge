# AGENTS.md

pixel-forge: a TypeScript pixel-art editor/animator with pixel-aware rigs (RotSprite, variants, overrides).
Headless core shared by a CLI (`pf`), an MCP server, a later web editor and a Godot import plugin.

## Session protocol

1. Start from `docs/STATUS.md`, then the task board and your card in `docs/02-plan.md`. Do not read the whole spec.
2. Context pack: this file, the target package README, the spec sections named on the card, the named files, one exemplar test.
3. Subagents never commit. Leave changes in the worktree and report files changed, commands run, doubts.
4. The orchestrator verifies (acceptance commands, public API diff, upscaled golden sheets), then commits and merges. Never trust "done" alone.
5. Parallel (marked with the parallel symbol) cards run in isolated worktrees.
6. Never use bare `git stash`: the stash stack is shared by every worktree. To set work aside, make a temporary WIP commit in your own worktree.

## Definition of done

- `pnpm verify` passes: lint, typecheck, test, depcruise, `gen --check`.
- Tests written alongside or before logic; coverage of the touched core package stays at or above 85%.
- No `any`, no `Math.random`, no `Date.now()` in pure packages.
- Public API has TSDoc; update docs the change made stale (README, contracts, KNOWN_ISSUES, PLAYBOOKS).
- User-visible change adds a changeset (`pnpm changeset`).

## Conventions

- Node 26, pnpm pinned via `packageManager`, TS project references, ESM only, Vitest, tsup, changesets.
- Packages: `png`, `testkit`, `schema`, `color`, `raster`, `rig`, `convert`, `core`, `lint`, `io`, `ops`, `server`, `cli`, `editor`, Godot addon. Dependency order is enforced by dependency-cruiser.
- Layering: `rig` = pure functions over schema types (evaluatePose, renderParts, jointCheck, overlapMask, attributeEdit, pose clipboard maths). `core` = document-level operations (split transaction, bake via `renderFrame`, mirror inside `renderFrame`, rig render hook). Each card names its package.
- Pure packages (`schema`, `color`, `raster`, `rig`, `convert`, `core`): no DOM, no Node built-ins. `io` uses a `FileSystem` port.
- Coordinates: origin top-left, y down, angles in degrees clockwise, integer pixels, pivot at the pixel centre.
- Determinism: integer/fixed-point maths, fflate only, hash decoded RGBA (ADR-010).
- Contracts (file schema, op API, `__pf`) change additively; breaking change needs an ADR and a migration.
- Fixtures: `fixtures/` holds synthetic art generated by committed scripts in `fixtures/src/`, plus CC0 art in `fixtures/cc0/` with its licence file. Never commit licensed or third-party game art.

## Public-repo hygiene

- This repo is public (MIT). Commits use the repo-local pseudonymous identity `pixel-forge dev <dev@pixel-forge.invalid>`; never the global git identity.
- Never commit game-specific identifiers, art-pack names or absolute home-directory paths. The first consumer game's details live only in the untracked `~/pf-work/GAME_NOTES.md`. Public docs say "the first consumer game".
- `scripts/privacy-check.sh` runs as a pre-commit hook and rejects absolute home paths and terms in a local denylist.

## Licensing of code

- Never copy or port code from non-permissive sources. That includes Aseprite (proprietary EULA), GPL projects such as LibreSprite, and anything without a licence. Comparing *outputs* against such tools is fine.
- Implement algorithms from papers or permissively licensed or public-domain references, and name the source in TSDoc. If in doubt, ask the orchestrator.

## Oracles and goldens

- Prefer independent oracles: hand-written ASCII expectations, property tests, external tools (Aseprite CLI, pngjs, sips, Godot).
- A golden produced by the code under test is accepted only after someone has looked at the upscaled sheet (`pnpm golden:sheet <name>`); the card Notes say "golden reviewed".
- Update goldens only with `UPDATE_GOLDEN=1` plus a note on the card.

## Code is the source of truth

Docs describe and test contracts; when they disagree with the code, fix the docs (or the code, via a card). Record new problems in `docs/ai/KNOWN_ISSUES.md`.
