# ADR-001: Option D: greenfield headless-core TypeScript app

- **Status**: Accepted
- **Date**: 2026-10-26

## Context
We need a pixel-art editor and animator with pixel-aware rigs that an LLM agent can drive before any UI exists, plus a game-engine importer. The alternatives (extending an existing editor, scripting one, building inside the engine) either capped the rig model or tied us to someone else's file model.

## Decision
Build a pure TypeScript core library (document model, operations, undo, palette, rig, RotSprite, renderer) and make everything else a client of it: CLI (`pf`), MCP server, a web editor (M2), a Godot importer plugin, and optional `.aseprite` import. The UI is one client among several.

## Consequences
- Full control of the rig model, which is the differentiator.
- Claude Code can use the tool from the first milestone through MCP.
- Highly testable and cheap-model friendly.
- Cost: editor basics (tools, selection, timeline) must be built; delivered incrementally, UI last.
