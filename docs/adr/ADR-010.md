# ADR-010: Determinism rules

- **Status**: Proposed
- **Date**: 2026-10-26

## Context
Byte-identical output across platforms cannot be verified when codecs, `Math.sin` and timestamps vary (R-12). Rig snapping and goldens require reproducibility. Status is Proposed until fixed-point trig (T1.6) is implemented and the hash suite passes on both CI platforms.

## Decision
Determinism means the same document plus operations yields the same hash of decoded RGBA on macOS, Linux and Windows. Rules: integer maths in the render path; a fixed-point sin/cos table at the angle quantum; no `Math.random` (seeded PRNG only) and no `Date.now()` in pure packages; a pinned pure-JS deflate (fflate) for all encoding; sorted JSON keys, fixed zip order and timestamps; hash decoded pixels, not file bytes.

## Consequences
- Goldens and cross-platform CI hash suites are meaningful.
- Slightly more work in raster/rig (no float trig shortcuts).
- Files are byte-stable within one pf version, not across versions.

## Evidence
T1.6 (`packages/raster/src/trig.ts`, README "Rotation"):
- **Table**: Q16 (×65536) sine at 0.25° (1440 entries), stored as a committed 361-entry quarter wave in `trig-table.ts`. It is generated by `packages/raster/scripts/gen-trig-table.mjs` with exact BigInt maths (256 fractional bits, Machin's pi, Taylor series) and expanded at load by exact integer symmetries. The runtime never calls `Math.sin`/`Math.cos`.
- **Rounding**: half away from zero, both for table entries and for `rotatePoint` (`roundQ16`). No table entry is a tie: the closest fractional part is 0.0018 from .5, so a float64 `Math.sin` path gives the same 1440 values, but the committed integers are the contract. Exact at 0/90/180/270° and 30/150/210/330°. `sin(−x) = −sin(x)`, `sin(180° − x) = sin(x)` and `cos(x) = sin(x + 90°)` hold exactly. `|sin² + cos² − 65536²| ≤ 92683` (2.2e-5).
- **Integer range**: offsets up to ±2^31, so every product stays below 2^53 and IEEE doubles compute it exactly on every platform.
- **Float comparison**: `rotatePoint` differs from float64 `roundHalfAway(dx·cos − dy·sin)` only within `(|dx| + |dy|) / 131072` of a .5 boundary. That is 648 of 6.9 M coordinates at `|d| ≤ 24` over all angles, 136 of them exact Q16 ties such as `(1, 0)` at 30° → `[1, 1]`. This is the "documented .5 ties" rule T3.1's float64 oracle uses.
- **RotSprite**: every per-pixel decision is integer (`sfloor` of Q16 products by 8192, exact equality in Scale2x). A mirror-invariant tie rule makes mirror symmetry exact at all 1440 angles.
- **Hash evidence**: `packages/raster/test/rotsprite-hashes.json` commits the SHA-256 of the decoded RGBA (plus `pivotOut`) of `rotateAbout` output, RotSprite and nearest, for the four synthetic subjects at 10 angles (0.25° to 315°, including 90°); the test fails on any change. Update it only with `UPDATE_GOLDEN=1` plus a card note, after reviewing the sheet. A test also stubs `Math.sin/cos/tan/atan2` (and the other trig functions) to throw and rotates every subject at 206 angles with both algorithms, showing the render path only uses the committed table. These are the values the macOS/Windows CI runs must reproduce.
- **Range checks**: `roundQ16` accepts `|v| ≤ 2^53 − 32768` (the exact limit of its maths) and throws `BAD_VALUE` beyond; `RotSprite` throws `BAD_SIZE` above 2^18 opaque px at every angle.
- **Not yet shown**: the cross-platform hash suite (macOS and Windows CI) has not been run, so the Status stays Proposed until G1.
