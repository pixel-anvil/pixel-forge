# ADR-004: Single document owner with snapshot sync

- **Status**: Accepted
- **Date**: 2026-10-26

## Context
Several processes (an MCP server, a UI server, the engine importer) could open one `.pxf`, risking conflicting edits and half-written reads (R-04). Merge logic and proposal diffs were judged over-engineered (R-11).

## Decision
One process owns a document. Owners write a lockfile `~/.pixel-forge/locks/<sha1(path)>.lock` and `pf serve` writes `~/.pixel-forge/server.json` (pid, port, token, protocolVersion) for discovery; stale entries are detected by pid. A second process forwards to the owner if it is `pf serve`, or fails with `DOC_LOCKED`. Saves are atomic (tmp file then rename). The editor holds a read-model replica fed by patches in version order and requests a full snapshot on connect or any gap. There is no merge logic. MCP edits apply directly, one undo step each.

## Consequences
- Simple, debuggable concurrency model with no CRDT or merge machinery.
- Headless use works without a server (in-process DocumentHost).
- Latency of a forward hop; large snapshots on reconnect.
