# ADR-003: Operation API as a zod registry

- **Status**: Accepted
- **Date**: 2026-10-26

## Context
CLI, MCP, UI, the check harness and a future AI panel must all mutate documents identically. Hand-written adapters per transport drift and are expensive to keep documented.

## Decision
Define each operation once with `defineOp({name, safety, summary, input, output, examples, handler})` using zod. The registry generates MCP tool JSON, CLI subcommands, `__pf.run` typings and `docs/contracts/OPERATIONS.md`; CI checks the generated files are current. Handlers mutate only through `ctx.tx` and do no direct I/O. Errors are typed `OpError {code, message, details}` and serialised the same on every transport. Indices are resolved to IDs at the boundary.

## Consequences
- One definition yields tools, CLI, docs and tests; adding an op is a playbook, not a project.
- The registry framework (T5.1) is a high-leverage contract and gets an Opus card plus review.
- Contracts change additively; a breaking change needs an ADR and a migration.
