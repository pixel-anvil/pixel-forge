# ADR-002: Package graph and layering

- **Status**: Accepted
- **Date**: 2026-10-26

## Context
The first spec draft had a self-contradicting package order (R-05), and plan cards broke the graph by putting document-level work in the pure rig package (P-01).

## Decision
Adopt the explicit graph of spec 6.2: `png` and `schema` at the bottom, then `color`, `raster`, `rig`, `convert`, `core`, `lint`, `io`, `ops`, `server`, `cli`, `editor`. A `testkit` package supports tests. `rig` holds pure functions over schema types; `core` holds document-level operations (split, bake, mirror inside `renderFrame`, the rig render hook). `schema`, `color`, `raster`, `rig`, `convert` and `core` use no DOM and no Node built-ins; `io` takes a `FileSystem` port. Enforced by dependency-cruiser in CI.

## Consequences
- Illegal imports fail CI, so layering cannot erode silently.
- Every card names its package, which keeps parallel work from colliding.
- Some features straddle two packages (rig maths vs core transaction) and need a hook interface defined early (T2.1).
