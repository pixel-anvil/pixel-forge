# ADR-007: Sparse tiles and patch-based history

- **Status**: Accepted
- **Date**: 2026-10-26

## Context
A dense worst case (256x256, 64 layers, 300 frames) is about 19 GB (R-20). Undo must be cheap and the editor needs patches to sync.

## Decision
Documents are immutable JSON plus sparse copy-on-write 16x16 tile stores. A transaction records structural (JSON-patch style) and tile before/after patches; undo applies inverses; one linear stack per document. `store.version` is a **runtime** counter, not saved in the document. It increases by 1 on every commit, undo and redo, so it is monotonic and is used for sync gap detection and proposal checks. The undo cap counts tile bytes.

## Consequences
- Memory scales with painted area, not canvas area.
- The same patches drive undo, journal and editor sync.
- Tile boundaries must be handled by every raster routine; testkit property tests cover this.
