# @pixel-forge/ops

Op registry, definitions, handlers, error types and generators (MCP tool JSON, CLI, docs).

**Depends on:** `core`, `lint`, `io`, `rig`, `convert`, `color` (palette maths for the `palette` ops, E5.2), plus `schema` (reference and value schemas; added to the dependency-cruiser table in T5.1), `raster` and `png` (grid and render ops build images and encode PNG, T5.3) and `zod`. No Node built-ins (eslint and dependency-cruiser enforce it): files go through the host's `FileSystem` port.

**Status:** T5.1: `defineOp`, the registry, `OpContext`, `OpError`, safety classes, `confirm`, reference resolution, the `OpHost` interface with an in-memory host, the generators, and the exemplar ops `doc.open`, `doc.summary`, `rig.setPose`. ## Use

```ts
import { createMemoryHost, registry } from '@pixel-forge/ops';
import { MemoryFileSystem, fixedClock } from '@pixel-forge/io';

const host = createMemoryHost({ fs, clock, roots: ['/work'] }); // server (T5.4) has the real host
const run = { host }; // also: labelPrefix (default 'AI: '), log, validate (default true)
const { doc } = (await registry.execute('doc.open', { path: '/work/hero.pxf' }, run)) as {
  doc: string;
};
await registry.execute(
  'rig.setPose',
  { doc, animation: { group: 'default' }, frame: 0, bones: { upper_arm_r: { angle: -45 } } },
  run,
);
const r = await registry.call('doc.summary', { doc }, run); // envelope, never throws
// r = { ok: true, op, output, doc: { id, version, undoEntry, canUndo, canRedo }, warnings? } | { ok: false, op, error: { code, message, details } }
```

## Ops

`defineOp({ name, safety, group, summary, description?, input, output, examples, transaction?, mcp?, cli?, handler })` checks the definition when the module loads (`group` is one of `TOOL_GROUPS`, a required field, see "Tool groups" below; name grammar `area.verbNoun`, one-line summary of at most 200 characters, object input, a `doc` field on mutate/destructive ops, no `confirm` field, at least one example whose input (and output, if given) parse) and derives `mcpName` (`rig_set_pose`), `cliCommand` (`['rig', 'set-pose']`), `targetsDocument` (the input has `doc`) and `transactional`.

| Safety        | Handler | Transaction                                                                      |
| ------------- | ------- | -------------------------------------------------------------------------------- |
| `read`        | sync    | none; `ctx.view` is the live store                                               |
| `mutate`      | sync    | the registry opens one (`ctx.tx`), commits after the output check: one undo step |
| `destructive` | sync    | like `mutate`; the registry adds `confirm` and refuses with `CONFIRM_REQUIRED`   |
| `io`          | async   | none, or one via `ctx.transact(fn)` (at most once per call)                      |

`transaction: false` (mutate/destructive only) skips the transaction for the history ops (`doc.undo`/`doc.redo` call `ctx.document.store.undo()`).

## Tool groups

Every op has a required `group` (`TOOL_GROUPS` in `src/groups.ts`: `core`, `rig`, `palette`, `convert`; `TOOL_GROUP_INFO` says what each holds; `parseToolGroups` reads a `--tools` list). A transport lists only some groups to keep the tool list small: `pf mcp --tools core,rig` (TG.1). `core`: doc, frame, anim, layer, cel, io, render, pixels, lint, pxf. `rig`: rig, part, override. `convert`: convert.imageToSprite, convert.apply (E4.5, below). `palette`: palette.edit, palette.sort, palette.ramp, palette.generate (an indexed document's pixels, ramps and remap skins follow every index change through core's `remapPaletteIndices`), palette.remap (below), skin.set (below). Add a group by extending both constants; the compiler fails until `TOOL_GROUP_INFO` has the new entry.

`palette.remap` (E5.4, FR-PAL-05; `palette_remap`, CLI `pf palette remap`) recolours drawings without changing the palette indices' meaning, or swaps the palette. Give exactly one of `map` and `swap`. The pure tables live in `@pixel-forge/color` (`indexLut`, `colorTable`, `swapPairs`, `applyIndexLut`, `applyColorTable`; `skin.set` uses `indexLut` for its `map`); the drawing walk is `src/recolor-drawings.ts`.

- `map`: `[{from, to}]`. An indexed document maps palette indices; an RGBA document maps exact `#rrggbb[aa]` colours (alpha must match). The table applies at once (1 to 3 and 3 to 1 swaps two entries). Unlisted pixels stay; transparent pixels stay (a transparent palette entry, or an alpha-0 colour, as `from` or `to` is `REFUSED`, `reason: 'transparent'`; erase with `pixels_write_grid`). Scope: all drawings by default (cels, rig part variants, override `set` images); `layer` and/or `animation` + `frames` limit it to the **cels** that own a drawing (a linked cel follows its source; a drawing shared with an out-of-scope cel is copied, so the other cel keeps its colours). Indices beyond the palette, the wrong kind of entry for the mode, a repeated `from` and unknown layers or frames are `BAD_INPUT`/`NOT_FOUND`.
- `swap`: `{palette: id}` (another palette of the document) or `{colors: [...]}`, the same count as the active palette. The active palette keeps its id, name and ramps; entry `i` gets the new colour. Indexed pixels change colour by themselves; RGBA pixels equal to old entry `i` become new entry `i` (a swap is `REFUSED`, `reason: 'swap'`, when one old colour appears twice with different new colours). Transparency must stay in the same entries (`reason: 'transparency'`). Whole document only. It works on palette-locked documents and leaves them on the new palette.
- Palette lock (RGBA): a `map` whose `to` colour is not a palette entry is `REFUSED` (`reason: 'off-palette'`, nothing changed). E5.2's `palette.edit` only warns because there the palette itself moves; here the result is known in advance, and `pixels.writeGrid` already refuses the same way. Lint `palette.offPalette` still judges the render.
- Output: `changed` pixels in all, `drawings` (changed ones, with `where` and `changed`), `scanned`. Nothing changed means no undo step. One undo step `AI: palette.remap`. Skins are not touched: remap skins are index tables of their own and palette skins pair entries by index, so a swap changes what they show.

**`skin.set`** (E5.5, FR-PAL-07; `skin_set`, CLI `pf skin set`; group `palette`) creates, replaces or removes a skin. `skin` is a name (not `base`) or an id; give exactly one of `map`, `palette`, `colors`, `remove`. `map` is a remap skin: `[{from, to}]` over the active palette, by index or by the exact colour of a palette entry (lowest index), built with `indexLut` and stored canonical (sorted, no identity pairs); a transparent entry is `REFUSED` (`reason: 'transparent'`); a `from` whose colour also sits at a lower index gets a warning (render step 8 matches by colour, lowest index wins, so the pair would not fire). `palette` is a palette skin on another palette of the document (id or name, never the active one); a shorter palette is a warning. `colors` makes a palette skin with a new palette `skin:<name>` (one colour per active entry; an opaque base entry needs an opaque skin colour). The same name replaces the skin and keeps its id and place; a replaced or removed skin takes its own `skin:<name>` palette with it when nothing else uses it. A document without an active palette is `REFUSED` (`no-palette`). One undo step `AI: skin.set`. Skins never touch pixels; they apply at render time, so `render_frame`, `io.export`, the `.pxf` render cache and `lint` (`palette.offPalette` renders every skin; FR-PAL-06) all see them. **E5.2's refusal stays:** `palette.edit`/`palette.sort` that move or remove an index are refused while a palette skin exists (`reason: 'palette-skin'`). Applying the same permutation to the skin palette is not small or safe enough: a skin palette may be shorter than the base palette (indices past its end keep the base colour), may be shared by several skins, and a removed entry has no place in it. Remove or rebuild the skin, edit the palette, add the skin again.

**`io.export` with `allSkins: true`** (E5.5) writes one sheet per skin from the same layout: `<name>.png` and `.json` for `base`, `<name>.<skin>.png` and `.json` for each skin, in document order; `meta.image` names its own PNG, the frame table is the same. The result adds `sheets: [{skin, png, json}]`; `png` and `json` stay the base sheet. All skins render before any file is written. `allSkins` and `skin` together are `BAD_INPUT`. The `.pxf` render cache already holds `render/<skin>/...` for every skin (E4.x), which is what the Godot importer reads (one atlas per skin).

**`convert.imageToSprite`** (E4.5, FR-CONV-01..09; `image_to_sprite`, CLI `pf convert image-to-sprite`; group `convert`; safety `io`) reads a PNG inside the workspace roots (`io.decodeImageFile`: JPEG and WebP are `REFUSED` with "convert the image to PNG first") and opens a NEW document (canvas = result size, animation `default`, one frame, no undo entries, like `doc.create`). Input is either shortcut fields (`crop` [x,y,w,h], `background` none/key/flood/alpha + `tolerance`, `grid` "auto" or a cell size, or `width`/`height`, `method`, `clean`, `outline`, `palette` preset id or `#rrggbb` list, `colors` N to make a palette, `dither`, `strength`) or one `recipe` (a `ConvertRecipe`; not both). Defaults: with a size target `method` kcentroid, with a grid `mode`; clean-up on; quantising when any of palette/colors/dither is given. A quantise step with no palette makes one of 16 colours from the result (`generatePalette`). The palette used is added to the document and made active. `variants` (`method`, `dither`, `palette` ids; cap 64, `TOO_MANY_VARIANTS` is `REFUSED`) makes one layer per combination (named from the label, `method-box_dither-bayer4`), the first visible. Output: `doc`, `canvas`, `layers`, `palette`, `steps` (size after each step) and `grid`. Errors of the converter map as `BAD_RECIPE`, `BAD_OPTION`, `BAD_RECT`, `BAD_PALETTE`, `BAD_AXES`, `BAD_IMAGE` to `BAD_INPUT`, and `NO_GRID`, `TOO_MANY_VARIANTS` to `REFUSED`. Sources over 4096x4096 pixels are `REFUSED`.

**`convert.apply`** (E4.5; `convert_apply`, CLI `pf convert apply`; group `convert`; safety `io`) runs the same steps on the cel of `layer` at `animation`/`frame` (read as a canvas-sized image). Without `newLayer` the result replaces the cel and must have the canvas size (so no downscale or outline); with `newLayer` it is a new layer, aligned so the result's bottom-centre sits on the document origin (a full-canvas result sits at 0,0), and must fit the canvas. One undo step `AI: convert.apply`. Quantising uses the active palette unless `palette` or `colors` is given. Refused: a linked cel (`linked-cel`), an indexed document (`indexed-document`), colours outside a palette-locked document's palette (`off-palette`), a result of another size (`size-mismatch`, `larger-than-canvas`), a used layer name (`layer-exists`). With `variants` the document is not changed: a NEW document holds one layer `variants` with the contact sheet (`variantSheet`, no scaling, 2 px gap), and `tiles` gives each combination's `label`, `x`, `y`, `w`, `h`.

**`palette.generate`** (E5.3, FR-PAL-04) makes a palette of 2 to 256 colours from a PNG file or from a frame (or one layer's cel) of the open document: k-means++ in OKLab (default) or median cut, in `@pixel-forge/color` (`generatePalette`, pure). It is an `io` op because the PNG source needs an async read; without `add: true` it only returns the colours and records no undo step. `add: true` stores a new palette (`name`, default "generated") and makes it active only if the document had none, or with `activate: true` (refused for an indexed document that already has a palette). The CLI needs `--save` to keep it. Rules: pixels with alpha below `minAlpha` (default 1) are ignored; other pixels count with their straight RGB; colours are opaque, all occur in the image, distinct and sorted darkest first (OKLab lightness, ties by RGB). An image with `n` colours or fewer returns its own colours (fewer than `n`, with a `note`). The image is never sampled: distinct colours are counted exactly, and above 8,192 of them they are merged into coarser cells first (`note` says so); more than 16,777,216 pixels are refused. The seed (default 1) only affects k-means; median cut is deterministic by itself.

## Registry

`createRegistry(ops)` (duplicate names, MCP names or CLI commands throw). `registry` is the built-in one (`ALL_OPS`). `execute(name, input, run)` resolves to the parsed output or rejects with an `OpError`; `call(...)` returns an envelope. Per call:

1. `UNKNOWN_OP` if no op has that name; the input must be a JSON object (`BAD_INPUT`); destructive ops: `confirm` is taken out, the rest parsed, then `confirm !== true` is `CONFIRM_REQUIRED`.
2. A `doc` field is resolved to the hosted document (`NOT_FOUND`, `kind: 'doc'`, with the open ids and a hint to call `doc_open`).
3. Transactional ops (the commit sequence lives once, in `commit.ts`, shared with `ctx.transact`): `store.begin('<labelPrefix><op>')`, handler, output parsed by the op's schema (else `INTERNAL`, `reason: 'bad-output'`), **validate guard**, `commit()`. Any error cancels the transaction, so a failed call leaves no trace (same hash, same version, no history entry). If a change listener of the store throws, the change is already committed: the call succeeds and `warnings` (also sent to `log.warn`) names the failure; it is never reported as `INTERNAL`. A call that changes nothing records nothing (`undoEntry: null`, core no-op detection), so a call adds at most one undo entry.
4. The validate guard (`run.validate`, default on) refuses a change that raises the per-code count of `validate()` errors (`INTERNAL`, `reason: 'invalid-document'`, first findings in `details`). The "before" counts are memoised per store version (never for a rejected state, so retries, pixel-only edits, undo and redo cannot see stale counts), and the pixel content checks of `validate()` (`options.images`) run only for images the call changed (all images when the palette or colour mode changed). Pre-existing errors of an opened file do not block ops.
5. Handlers that return a promise where they must be synchronous are `INTERNAL` (the transaction is cancelled).

## Context (`OpContext`)

`op`, `safety`, `host`, `renderer` (the host's single `RigRenderer`, KNOWN_ISSUES CORE-03), `log` (`debug`/`info`/`warn`, default silent), `hasDocument`, `document` (`HostedDocument`: `id`, `store`, `path`, `file`, `savedVersion`), `view` (the open transaction, else the live store), `doc` (`view.doc`), `tx` (transactional ops only), `transact(fn)` (io ops only, once; same label, same validate guard; call it last: a change it committed stays if the handler fails afterwards), `renderFrame(anim, frame, opts)` (`renderFrame` with the host renderer). Misuse throws `INTERNAL`.

## Errors

`OpError {code, message, details}` with `toJSON()`; codes in `OP_ERROR_CODES` (additive): `BAD_INPUT`, `UNKNOWN_OP`, `NOT_FOUND`, `AMBIGUOUS`, `CONFIRM_REQUIRED`, `REFUSED`, `INVALID_VALUE`, `NOT_ALLOWED`, `DOC_LOCKED`, `CONFLICT`, `BAD_FILE`, `IO_FAILED`, `NOT_IMPLEMENTED`, `INTERNAL`. `toOpError(e)` maps lower-package errors (KNOWN_ISSUES CORE-02):

- `CoreError` `BAD_ARGUMENT`: `details.reason` `unknown-*` -> `NOT_FOUND` with `details.kind` (`animation`, `frame`, `bone`, `view`, `part`, `variant`, `override`), any other reason -> `REFUSED`; `BAD_VALUE` -> `INVALID_VALUE`; `IMAGE_MISSING` -> `BAD_FILE`; `PATCH_CONFLICT` -> `CONFLICT`; `ID_EXHAUSTED` -> `REFUSED`; transaction misuse and `NO_RIG_RENDERER` -> `INTERNAL`. The core `details` are kept (JSON-safe values only).
- `IoError`: `FS_FAILED` -> `IO_FAILED`; `BAD_PXF`, `INVALID_DOCUMENT`, `UNSUPPORTED_VERSION`, `MIGRATION_*` -> `BAD_FILE`; `BAD_INPUT`, `CELL_OUT_OF_RANGE` -> `BAD_INPUT`; `SIZE_MISMATCH`, `DUPLICATE_ANIMATION`, `TOO_LARGE` -> `REFUSED`; `EXISTS` -> `CONFLICT`; `RIG_REQUIRED` -> `INTERNAL`. `AseError` -> `BAD_FILE`.
- `RigError`: `UNKNOWN_*` -> `NOT_FOUND`, `BAD_VALUE`/`BAD_QUANTUM` -> `INVALID_VALUE`, `BAD_ARGUMENT`/`CYCLE` -> `REFUSED` (with `reason`), `IMAGE_MISSING`/`DUPLICATE_BONE` -> `BAD_FILE`. `JointCheckError` -> `INVALID_VALUE`. `ZodError` -> `BAD_INPUT` (`details.issues: [{path: 'a.b', message}]`).
- Anything else -> `INTERNAL` (`details.cause.error`: the class name). Every mapped error has `details.cause: {error, code}`.

## References

Schemas for inputs: `DocRef`, `AnimRef` (`{group, direction?}` or `{id}`), `FrameRef` (index or id), `LayerRef`, `BoneRef`, `PartRef`, `ViewRef`, `VariantRef` (strings). Resolvers over `ctx.doc`: `resolveAnimation`, `resolveAuthoredAnimation` (mirror -> `REFUSED` `mirror-animation` with the source label), `resolveFrame` (`NOT_FOUND` with `count`), `resolveLayer` (id, name or `group/name` path), `resolveBone`, `resolvePart` (part id, part-layer id or part-layer name), `resolveView`, `resolveVariant(part, ref, viewId?)` (a name is looked up in `viewId`'s variants first: names repeat across views), `viewForAnimation`, `requireRig` (`REFUSED` `no-rig`), plus `walkLayers`, `partName`, `animationLabel`. Rule: **an id match wins, then the name**; no match is `NOT_FOUND` with `details.available` (at most `MAX_AVAILABLE` = 50), several are `AMBIGUOUS` with `details.candidates` (ids).

## Host

`OpHost`: `fs`, `clock`, `renderer`, `resolvePath(path)` (normalise; workspace roots -> `NOT_ALLOWED`), `get(id)`, `byPath(path)`, `list()`, `adopt({store, path?, file?})` (registers a document; `CONFLICT` for a duplicate id or path; the server host takes the lockfile here and raises `DOC_LOCKED`), `adoptFile?(path, read)` (optional; `doc.open` uses it so a locking host takes the lock before the file is read, and releases it if `read` fails; without it `doc.open` reads, then `adopt`s), `close(id)`. Documents are addressed by their own `meta.id`. `createMemoryHost({fs, clock, roots?, renderer?})` is the in-process implementation without lockfiles; `normalizePath` folds `.`/`..`.

## Generators

`mcpTools(registry)` (MCP `Tool` objects: `name`, `title`, `description` = summary + description + safety note + conventions + first example, `inputSchema` with `confirm` for destructive ops, `outputSchema` when the output is an object, `annotations` `readOnlyHint`/`destructiveHint`/`openWorldHint: false`, `_meta` with the op name, safety and `pixel-forge/group`), `cliMetadata(registry)` (per command: words, summary, safety, one option per top-level input field with `kind` `string`/`integer`/`number`/`boolean`/`json` and string-enum `choices`), `operationsMarkdown(registry)`, `generatedFiles(registry)`. JSON Schemas come from `toJsonSchema` (zod `toJSONSchema`, draft 2020-12, `io: 'input'` for inputs; no `$schema`, no safe-integer bounds, no reserved-name lookahead in name patterns: zod stays the authority). Ops hidden with `mcp.hidden` / `cli.hidden` are left out of that transport.

`packages/ops/scripts/gen-ops.mjs` (run by `pnpm gen`; `pnpm gen:check` in `pnpm verify` fails on a stale copy) builds the package incrementally and writes `packages/ops/generated/mcp-tools.json`, `packages/ops/generated/cli.json` (prettier-formatted) and `docs/contracts/OPERATIONS.md`. The committed copies are review snapshots of the contract; the MCP server (`@pixel-forge/server`, T5.5; it drops `outputSchema` from `tools/list`) and the CLI (T5.6a) build from the registry at run time. Every MCP tool description (summary, description, `confirmText`, safety note, conventions, first example) is held to 800 characters by a server test.
